RNN 怎么给 VMC
当采样器

你已经会搭 MLP、也知道 VMC 在做什么。这一页只讲一件事：把 MLP 沿时间复用，怎么就变成了一个能按 |ψ|² 逐位吐出样本的采样器。没有 RNN 先修要求，全部从你已有的东西推出来。

你的起点

MLP 前向、one-hot 编码、NetKet/VMC 基本流程；见过 Metropolis 采样与 SR 更新。没写过 RNN。

走到哪里

看懂展开图与隐藏状态；能手写逐位采样循环；明白 conditional(x,i) 接口、VMC 里的比值/局域能量/梯度，以及 RNN 相比掩码网络的真实取舍。

00

先看清你手里这套机器缺了什么

你现在会的东西已经很多了：一个 MLP 吃进构型 x = (x1, …, xN) 的 one-hot 编码，吐出一个复数 ψθ(x)；VMC 用 Metropolis 在 |ψθ|2/Z 上游走，估能量、估梯度、更新参数。这套流程里，网络只负责给一个完整构型打分，"怎么得到样本"完全交给外挂的采样器。

于是有两件事一直不太舒服：

  • 样本是相关的。MCMC 的连续样本沿马尔可夫链排列，误差条要除自相关时间，burn-in 得丢，步长与接受率得调。
  • MLP 没有"半成品"状态。它必须吃进整条构型才有一个输出。你没办法问它："已经生成了前三位，第四位取 1 的概率是多少？"——而这恰好是自回归采样每步要问的问题。

RNN 补的正是第二点。它把"一次算完"改成"一位一位算"，网络内部从此有了一个随位置推进的状态 ht；于是采样不再是"在构型空间里随机游走"，而是按条件概率逐位生成。

MLP：x1..N  →  MLP  →  ψ(x)    （一次性）
RNN：x1 → h1 → p1，x2 → h2 → p2，…  （沿时间推进，cell 复用）
先纠正一个预期 RNN 不是"更深的 MLP"，也不是唯一正确的自回归结构。NetKet 3.21 里现成的 ARNN（ARNNDense、ARNNConv1D/2D）用的是掩码全连接，不是循环网络。它们能配 ARDirectSampler，是因为都满足同一个接口：conditional(x, i)。这一页想让你真正拿到的是——RNN 凭什么满足这个接口，以及满足它的代价是什么。
01

采样器其实只要交三份作业

把"采样器"三个字拆开，VMC 对它的需求只有三件：

作业数学形式Metropolis 怎么交自回归怎么交
给构型打分log ψ(x)要，用来算接受率与能量要，训练与局域能量都要
批量出样本{x(b)} ~ |ψ|2/Z马尔可夫链游走，样本相关逐位祖先采样，样本独立
回答条件概率p(xi | x<i)不需要核心接口，每一步都问

NetKet 把这个"核心接口"定得很窄。下面是 ARDirectSampler 文档里的原话（我在本环境 netket 3.21.0 里核对过）：

ARDirectSampler 对模型的要求（真实 API）
# model.conditional 必须返回第 index 位的条件概率
p = model.apply(variables, σ, index, method=model.conditional)
# σ     : (batch, N) 半成品构型，index 之前的位已经采好
# index : 当前要决定的位 i, 调用顺序严格是 0, 1, 2, ...
# p     : (batch, local_size)，例如自旋 1/2 就是 (batch, 2)

注意这句话的分量：采样器只关心"给定前缀，第 i 位取各值的概率"。它不关心你的网络是掩码全连接、卷积、还是循环的；也不关心你是重算整张网络还是复用缓存。只要这个函数能按 i = 0, 1, …, N−1 依次给出正确结果，采样就是精确的。

一句话把问题转成设计题： 一个 MLP 只能回答"整条构型的分数"，而采样器要问"前缀已知时下一位的分布"。
RNN 的整个构造，就是为了让网络每读一位就顺手把"下一位的预测"算出来，并且这个预测在构造上只能看见已经读过的位。
02

RNN 的最小定义：一个多了一根输入线的 MLP cell

先把神秘感去掉。你熟悉的 MLP 隐藏层是 f(x) = tanh(Wx + b)。RNN 的 cell 只是在这个式子右边再加一项：

ht = tanh( Wx xt + Wh ht−1 + b ) xt 是第 t 位的 one-hot（自旋 1/2 时只有 2 维）；ht 是隐藏状态（常用 16–256 维）；Wx、Wh、b 在所有时间步上共用同一套。

再挂一个线性输出头，把它变成"下一位取 1 的概率"：

p(xt+1 = 1 | x≤t) = softmax(Wy ht + c)[1]

和 MLP 相比只有三个差别，每一个都对采样有用：

差别MLPRNN为什么采样需要它
输入整条构型一次性输入每步只喂一位 + 上一刻的状态天然支持"只生成了前缀"的半成品
参数每个位置独立权重跨时间共享一套权重参数量与 N 无关；"如何从任意前缀继续猜"是同一个函数
输出一个标量 ψ(x)每个时间步一个条件分布正好就是 conditional(x, i) 要的东西

参数共享不是为了省显存，而是语义上的选择：体系从 N=8 换到 N=16，你不需要重新设计第一层维度。MLP 第一层要 N×H 个权重，RNN 只要 H×H 加一个 2 列的 Wx。

展开图：同一个 cell 被复制 N 次

画 RNN 的标准方式是沿时间展开（unroll）：把同一个 cell 画成 N 份，用箭头把 ht−1 连到 ht。下面的交互里，我写死了一组 H=4 的小权重（就是页面里真正在算的那组）。你手动往里喂 0/1，观察两件事：

  • 每喂一位，四个隐藏单元怎样被改写（ht 的条形图）；
  • 改写后的状态怎样改变"下一位取 1"的概率（p 的百分比）。
交互 01  手动喂位，看 h 与 p 怎么变
箭头方向：xt 进 cell → 更新 ht → 输出头给出 p(xt+1=1)。注意 p 在开头是 0.54，喂过 1 之后跳到 0.83，喂 0 之后掉到 0.25——同一个 cell、同一组权重，答案随前缀而变，这正是"条件概率"。
起始状态从哪来 第一位没有前缀可看，所以需要一个起始状态 h0（可学习向量或零向量）。它负责给出 p(x1)。对应到 NetKet 的接口，就是 conditional(σ, 0)：此时 σ 里还没有任何有效位。
别把 h 当作精确记忆 ht 是定长向量，它只能压缩前缀信息。前缀越长、关联越复杂，压缩损失越大。这不是实现细节，而是 RNN 在长链 VMC 上的根本瓶颈（第 07 节展开）。
03

因果性：时间箭头 vs 掩码矩阵

你学 MADE 时最费劲的地方，是"怎么保证输出 i 看不到输入 i 及之后"。RNN 的回答非常干脆：因为它只读到这里。第 t 步的 ht 只由 x1, …, xt 算出来，而 p(xt+1) 只读 ht。未来的位在物理上还没进过网络。

MADE / ARNNDense

一次前向并行算出全部 N 个条件概率。因果性靠掩码从全连接图里"剪"出来：输出 i 的连接只允许指向输入 < i。被剪掉的连接永久闲置。

RNN

沿时间算 N 步，每步算出一个条件概率。因果性靠计算顺序保证：第 t 步根本拿不到 t 之后的数据。没有掩码，所有参数都在工作。

两者最终给出同一个分解：p(x) = Πi p(xi | x<i)。区别只在"一次算 N 个"还是"算 N 次"，以及下面这个可以点着玩的区别。

交互 02  点一个输出位，看它能看见哪些输入

MADE：4×4 连接矩阵，格子被掩码剪掉

点任意一行（输出位）。红色 = 该输出实际用到的输入；斜纹 = 被掩码禁止。允许集合是 {0, …, i−1}。

RNN：4 个时间步，状态单向前传

点任意一个 cell。它手里的信息只来自箭头左边，未来位没有任何路径能进来——不需要剪任何权重。
为什么这不只是"实现方式不同" MADE 的掩码是在组合结构上做手术：你要为每个输出位设计一行 mask，还要担心随机排列、集成多个 mask。RNN 的因果性是计算图自带的：你只要按顺序喂，就不可能作弊。代价也从这里来——MADE 一次前向拿到 N 个条件概率，RNN 必须老老实实走 N 步。
04

逐位采样：把输出喂回输入

现在把网络接到它自己身上。采样的循环就是把上一步采到的位当成下一步的输入：

# 祖先采样（ancestral sampling）：N 步，每步一个条件分布
h, x, logp = h0, [], 0
for i in range(N):
    p = softmax(Wy @ h + c)             # p(x_i | x_<i)，只看得到前缀
    x_i = sample(p)                      # 按 p 抽一次，0 或 1
    x.append(x_i)
    logp += log(p[x_i])                  # 顺手攒下精确的 log p(x)
    h = cell(h, x_i)                     # 把刚采的位喂回网络

循环结束时你拿到两样东西：一个样本，以及它精确的对数概率。后者不需要分母 Z——因为自回归结构已经保证 Σx p(x) = 1。

它和 Metropolis 差在哪

Metropolis自回归祖先采样
样本间相关性有，需要自相关时间无，样本严格独立
burn-in需要丢弃不需要
提议分布 / 接受率要调步长，可能拒绝不存在这套东西
每个样本的开销若干步局部更新，通常便宜N 次串行 cell 调用（batch 内可并行）
对模型的要求只要能算 log ψ，什么模型都行必须自回归，且暴露 conditional

下面这个 6 位采样器用的还是第 02 节那组玩具权重，只是把"手动喂"换成了"按概率自己抽"。单步点，或者让它自动跑完。

05

训练：teacher forcing，把整条序列一次性喂进去

采样时输入是自己刚吐出来的位；训练时千万别这么干。标准做法叫 teacher forcing：把数据里真实的整条 x 喂进去，让每一步都去预测"下一位的真实值"，然后把 N 个位置的损失加起来。

L(θ) = − Σi=1..N log pθ(xidata | x<idata) 这就是极大似然，也就是逐位交叉熵之和。和第 03 课 MADE 的训练目标完全一样，只是计算图从"一次前向"变成"沿时间扫一遍"。

两套流程的差别，只看"每步输入的来源"就够了：

训练 · teacher forcing

输入：真实数据的每一位。
输出：每位的条件分布。
损失：只取真实位对应的那个概率，取对数、求和、取负。
优点：一次拿到全部 N 个位置的损失，梯度稳定。

采样 · free running

输入：自己上一步采出来的位。
输出：下一位的条件分布。
损失：无，只累积 log p。
风险：一旦早期采错，后面全在错误前缀上继续推。

Flax 写法：共享权重就是"模块定义在循环外"
class ARRNN(nn.Module):
    N: int
    H: int = 32

    @nn.compact
    def __call__(self, x):              # x: (batch, N)，取值 0/1
        h  = self.param("h0", nn.initializers.zeros, (self.H,))
        Wx = nn.Dense(self.H, use_bias=True)   # 循环外定义 → 自动共享
        Wh = nn.Dense(self.H, use_bias=False)
        Wy = nn.Dense(2)

        logp = 0.0
        for i in range(self.N):
            h = jnp.tanh(Wx(jnp.eye(2)[x[:, i]]) + Wh(h))
            p = jax.nn.softmax(Wy(h))
            logp = logp + jnp.log(p[jnp.arange(p.shape[0]), x[:, i]])
        return logp                      # (batch,)，可直接送进 −mean(logp)
一个真实存在的偏差 teacher forcing 让模型只见过"正确前缀"。采样时它面对的是自己的输出，一旦偏离训练分布，条件概率可能没被训练过。这叫 exposure bias。短链、局部关联强的体系通常没事；长序列上它会让 RNN 采样质量变差——这是 RNN 相对掩码网络的一个真实弱点，不是理论洁癖。
06

接进 VMC：ψ = √p，剩下全是比值

到这里，采样器已经能工作了。VMC 还需要两样东西：局域能量和梯度。关键是不用重新发明任何东西——只要把波函数用 p 表示出来。

最简单的情形是实、正波函数：ψθ(x) = √pθ(x)，即 log ψ = ½ log p。更一般地，网络出两个头：ψθ(x) = exp(Aθ(x) + iBθ(x))，模长部分 A = ½ log p 用于采样，相位 B 只进能量。下面的推导先按实波函数走，相位只在最后提一句。

一、局域能量只需要比值

Eloc(x) = Hxx + Σx′ ≠ x Hxx′ · ψ(x′)/ψ(x) 关键恒等式：ψ(x′)/ψ(x) = exp( ½ [ log p(x′) − log p(x) ] )。所以每个翻转构型只需要一次 RNN 前向得到它的 log p。

对横场 Ising 这类只有单自旋翻转的哈密顿量，求和只有 N 项：

Eloc(x) = −J Σ⟨ij⟩ sisj − h Σi exp( ½ [ log p(xi) − log p(x) ] ) xi 表示只把第 i 位翻转得到的构型。第一项是"对角"部分，第二项来自每次翻转的矩阵元 −h。相位情形下比值多一个 exp(iΔB)。

二、梯度只差一个 ½ 和一个权重

∇θE = 2 Re ⟨ (Eloc(x) − E) · ∇θ log ψ(x) ⟩x~p
∇θ log ψ = ½ ∇θ log p

把第二式代进第一式，你会发现训练 RNN 的极大似然梯度就是 VMC 梯度的骨架：同样是 ∇log p，只是权重从"1"换成了 (Eloc − E)/2。03 课你有数据，去最小化 −log p；这里没有数据，你最小化 ⟨Eloc⟩。参数化是同一个，目标函数换了。

VMC 组件RNN 形态额外开销
采样祖先采样，逐位问 conditional每样本 N 步
归一化常数 Z不存在；Σx p(x) ≡ 10
局域能量对角项 + N 个翻转构型的 log p 比值N 次额外前向（可缓存前缀）
梯度⟨(Eloc−E)·∇log p⟩反向传播穿过 N 步
SR对 ∇log p 做同样的量子几何张量求解与模型无关
一个实用的小优化 翻转第 i 位后，前缀 x<i 没变，所以 hi−1 可以直接复用，只需要重算 i…N。N 个翻转全部共享前缀状态时，总开销从 N² 降到 N 量级。NetKet 现成的 ARNNDense 每次 conditional 都会从零重算，并不自动利用这一点；自己写 RNN 时这是你能拿到的实惠。

07

代价、坑，以及工程上到底该选谁

RNN 在 VMC 里真正的两个优势

  • 采样复杂度是 O(N)，不是 O(N²)。ARNNDense.conditional(σ, i) 内部调用 conditionals(σ)，把全部 N 个条件概率重算一遍；采样 N 次就是 O(N²)。RNN 的状态 ht 天然携带前缀，走一步只算一个 cell，整条样本 O(N)。NetKet 的 FastARNN* 系列就是靠缓存把 O(N²) 压回 O(N)——而 RNN 天生就有这个缓存。
  • 参数量与 N 无关。同一组 Wx, Wh, Wy 服务所有位置。体系变大时，模型不会跟着线性膨胀，这对 N 上百的链很有吸引力。

它的三个真实短板

短板为什么缓解办法
串行、难并行ht 依赖 ht−1，训练时也无法跨位置并行（掩码网络一次前向就能算完 N 个位置）batch 维并行；lax.scan；FastARNN 式缓存
长程记忆有损h 是定长向量，长链上的信息被不断覆盖；梯度还会消失LSTM/GRU cell；增大 H；换注意力 / Transformer
2D 上要人为排序自回归必须是一条 1D 顺序。行优先或蛇形顺序会让"序列上相邻"与"格点上相邻"脱钩蛇形顺序；用 ARNNConv2D 这类保留局部性的掩码卷积
顺序不是小事 同一个 4×4 格子，"行优先"和"蛇形"给出两个不同的自回归分解。后者让序列相邻的位在格点上也相邻，条件概率更容易学。更根本的是：无论怎么排，一个位只能看见它前面的位，所以二维里"右上方"的关联永远要绕一大圈。这是所有自回归 NQS 的共同限制，不是 RNN 独有。

组合采样一次前向参数量2D 局部性典型场景
MLP + MetropolisMCMC，有相关1 次N·H不涉及通用、稳健，教学与基线
ARNNDense（MADE）精确，O(N²)算出全部 N 个条件概率N·H弱（靠排列）NetKet 默认；小 N 很省心
ARNNConv（掩码卷积）精确，O(N²) 或缓存 O(N)并行与 N 弱相关强2D 格子、平移不变体系
RNN精确，O(N)串行 N 步H²，与 N 无关弱（需排序）长链、变长体系、教学
Transformer（自回归）精确，O(N²)并行大靠位置编码/注意力大规模、强长程关联
NetKet 3.21 的实际情况 本环境里 没有 nk.models.RNN（dir(nk.models) 只有 ARNN* 与 FastARNN* 系列）。要用 RNN 采样器，你得自己写一个 flax 模型并实现 conditional。好消息是接口很窄：ARDirectSampler 只要求这个方法和 reorder、machine_pow；坏消息是它会在 lax.scan 里以 traced 的 index 调用你，所以「按索引取第 i 步状态」这件事要写成可 JIT 的形式（或者干脆每次重算全部条件概率，接受 O(N²)）。
自己接一个 RNN 到 NetKet 的最小骨架（示意，未在本页运行）
import flax.linen as nn, jax, jax.numpy as jnp
import netket as nk
from netket.models import AbstractARNN

class RNNAR(AbstractARNN):
    H: int = 32
    machine_pow: float = 2.0

    @nn.compact
    def conditionals(self, x):        # x: (batch, N) → (batch, N, local)
        B, N = x.shape
        h0 = jnp.zeros((B, self.H))
        Wx, Wh, Wy = nn.Dense(self.H), nn.Dense(self.H, use_bias=False), nn.Dense(2)

        p0 = jax.nn.softmax(Wy(h0))          # 第 1 位只靠 h0
        def body(h, xt):
            h = jnp.tanh(Wx(jnp.eye(2)[xt]) + Wh(h))
            return h, jax.nn.softmax(Wy(h))  # 读入 x_t 后 → p(x_{t+1})

        _, p_rest = jax.lax.scan(body, h0, x[:, :-1].T)   # 只喂前 N−1 位
        p = jnp.concatenate([p0[None], p_rest])    # (N, B, 2)
        return jnp.swapaxes(p, 0, 1)                    # (B, N, 2)
    # conditional / __call__ / reorder 由 AbstractARNN 提供。

真正接进采样器时还有一个坑：ARDirectSampler 在 lax.scan 里以 traced 的 index 调用 conditional。上面这种"每次重算全部 N 个条件概率"的写法可以直接工作，但复杂度退化成 O(N²)；要拿到 O(N)，得像 FastARNN 那样把 hi 存进 cache 并按 index 动态取出——这也是现成 ARNNDense 比手写 RNN 省事的原因。

08

一页速查，三道自测

心智模型（四句话）
1. RNN = 一个多了一根 ht−1 输入线、且跨时间共享权重的 MLP cell。
2. 它的第 t 步输出就是 p(xt+1|x≤t)，因果性由计算顺序免费保证。
3. 采样 = 输出 → 抽样 → 喂回输入，N 步得到独立样本与精确 log p。
4. VMC 里取 ψ=√p，局域能量与梯度全部化成 log p 的差值与加权和。
你可能问简短回答
RNN 需要 MADE 那样的掩码吗？不需要。因果性来自"还没读到未来"，不是来自剪连接。
采样还需要 Metropolis 吗？不需要。祖先采样直接按模型分布出独立样本。
为什么不用除 Z？自回归参数化天然归一化，Σx p(x) ≡ 1。
½ 从哪来？因为 ψ=√p；若网络直接输出 log ψ，则没有 ½，改由 machine_pow=2 负责。
RNN 比 ARNNDense 强在哪？采样 O(N)、参数量与 N 无关；弱在串行、长程记忆和 2D 排序。
NetKet 里有现成 RNN 吗？3.21 没有。ARDirectSampler 只认 conditional，自己写 flax 模块即可接。

自测

1. 一个 N=6 的 RNN 采样器采一个样本，需要调用几次 conditional？每次调用能看到几位？
6 次，index = 0…5。第 i 次只能依赖已采的 i 位（index 0 时一位都没有）。这就是"因果性"在接口层面的体现。
2. 如果我把 log p(x′) 算出来是 −3.0，log p(x) 是 −2.2，ψ(x′)/ψ(x) 等于多少？
exp(½(−3.0 − (−2.2))) = exp(−0.4) ≈ 0.670。注意是 ½，因为 ψ=√p；若网络直接输出 log ψ，则指数是 −0.8。
3. 为什么不能用 free running（把自己采的位喂回去）来训练？
因为训练需要每个位置都有"正确答案"来算损失。free running 一旦早期采错，后面所有位置都在错误前缀上计算，损失既不可靠也不可并行；而且误差会沿时间累积。teacher forcing 用真实前缀切断了这条累积路径。
