## 一、结论（TL;DR）

**方案1 已跑通并验证成功。** 冻结 1 个本征态后，子空间哈密顿量
$H_\perp = H - E_0|\psi_0\rangle\langle\psi_0|$
的谱严格等于 $\{0\} \cup \{E_1,\dots,E_{15}\}$（数值误差 1.3e-15），其**变分基态就是原哈密顿量的第一激发态**（overlap² = 1.000000000000），且 NetKet 原生 VMC（采样 / SR / 优化器全部不改）直接在 $H_\perp$ 上训练即可收敛到该激发态。

但验证过程中发现了 **4 个必须注意的坑**（见第三节），其中两个会直接导致错误结果而不报错。

## 三、四个关键发现（重要）

### 发现 1：`hi.all_states()[0]` **不是** HF 行列式

H2_631G.py 里 `Hatree_Fock = hi.all_states()[0]` 打印出的 `[0 0 0 1 0 0 0 1]` 只是 NetKet 的**枚举顺序**恰从最高轨道开始，它实际是 |3α3β>（两电子都在最高空间轨道）：

- `<[0,0,0,1,0,0,0,1]|H|...> = +1.23688 Ha`（远高于基态，且 H|u⟩ − ⟨u|H|u⟩|u⟩ 范数 0.279 ≠ 0，**非本征态**）
- 真实 HF 行列式是 `[1,0,0,0,1,0,0,0]`，其对角元 = **-0.9974972943 == E_RHF**（机器精度验证）

**影响**：凡是把 `all_states()[0]` 当 HF 参考态/规范参考态/采样初态的代码，实际用的是一个高能激发组态。数学上仍自洽（规范参考任意非零组态均可），但物理含义与命名不符，采样初态尤其应当改成真实 HF。

### 发现 2：文档简化公式**只对严格本征态成立**

$$H_\perp \stackrel{\text{仅本征态}}{=} H - \sum_{m\in F} E_m|\phi_m\rangle\langle\phi_m|,\qquad \text{一般形式 } H_\perp = (I-P_F)H(I-P_F)$$

对非本征态 u（如 HF 行列式）套用简化公式会**静默失败**：`(H - E_u|u><u|)u = Hu - E_u·u ≠ 0`（实测范数 0.2788，冻结不干净）。两种情形的验证结果：

| 冻结态 | 用哪种公式 | 验证结果 |
|---|---|---|
| u = [0,0,0,1,0,0,0,1]（非本征态，Part A） | 一般形式 (I−P)H(I−P) | H_perp·u = 0（1e-16）✓；u⊥ 上二次型与 H 严格一致 ✓；最低 Ritz 值 = -0.95790573 == E₁（因 \|⟨u\|ψ₁⟩\|² ≈ 6e-36 ≈ 0，变分上界饱和）✓ |
| ψ₀ = FCI 基态（本征态，Part B） | 简化公式 H − E₀\|ψ₀⟩⟨ψ₀\| | 谱 == {0}∪{E₁..E₁₅}（max diff 1.3e-15）✓；基态 == ψ₁（overlap² = 1.0）✓；且数值验证 (I−P)H(I−P) == H − E₀P（本征态时两公式严格等价，diff 2.3e-15）✓ |

**对 NES-VMC 的含义**：冻结的是收敛后的变分态（近似本征态），简化公式可用，但正交性漂移会随训练累积——这正是原文档第四节"每 10~20 步重算一次重叠"的意义。

### 发现 3：把全空间矩阵塞进 `LocalOperator` 会**静默丢矩阵**

```python
nk.operator.LocalOperator(hi, H_perp_16x16)   # ❌ 不报错, 但矩阵被完全丢弃!
```

NetKet 的 `canonicalize_input` 对空 `acting_on` 会把 operators 清空（当成了"无常数项的空算子"）。正确做法是把 16×16 约束空间矩阵**嵌入 2⁸=256 全局域矩阵**，并显式给 `acting_on`：

```python
def wrap_full_matrix(M16):                      # M16: 16x16, 基矢顺序 = hi.all_states()
    M = np.zeros((2**hi.size, 2**hi.size))      # 256x256
    ps = [sum(int(bit) << (hi.size - 1 - k)     # 已验证: site0 是最高位 (MSB)
              for k, bit in enumerate(s)) for s in hi.all_states()]
    M[np.ix_(ps, ps)] = M16
    return nk.operator.LocalOperator(hi, M, acting_on=list(range(hi.size)))
```

位序约定经 roundtrip 验证为 **site0=MSB**（site0=LSB 时误差 2.23，完全错误）。包装后 `to_sparse()` 与显式矩阵逐元素相等（误差 0），`expect` 结果正确。

### 发现 4：VMC 求激发态的 ansatz 必须能表示**符号结构**

用 `H̃ = H_perp + λ·|ψ₀⟩⟨ψ₀|`（λ=+2，把冻结态方向的零模从 0 推高到 +2，**防止 VMC 塌缩回冻结态**；当目标能级 E_k > 0 时这步是必需的）+ FermionHopRule 采样 + SR 训练，三种 ansatz 对比：

| ansatz | 结果 | 原因 |
|---|---|---|
| 实参数 RBM（float64） | 卡在 **-0.7996**（远高于 E₁），与容量无关 | exp(实数) 恒正 → 只能表示正定波函数，-0.7996 是正定变分极限 |
| 复参数 RBM（alpha=4, 600 步） | **-0.9389**，距 E₁ 差 19.0 mHa，overlap²(ψ₁)=0.980 | 可表示符号结构，但存在局部极小（ansatz/优化层面限制） |
| 复参数 LogStateVector（16 参数精确可表） | **-0.95782 ± 1.2e-05 == E₁（3σ 内）**，overlap²(ψ₁)=0.9998 | 精确可表 → 严格证明 H_perp 的 VMC 变分基态就是第一激发态 |

三种 ansatz 训练出的态与冻结态 ψ₀ 的重叠² 均 < 1e-6（正交性保持 ✓）。

**对 NES-VMC 的含义**：激发态训练必须用复参数网络；收敛到局部极小应先怀疑 ansatz/初始化，而不是投影构造本身。

### 附：本机 netket 3.21 的 SR 兼容性坑

默认 `nk.optimizer.SR()`（QGTOnTheFly + jax CG）在求 `S·x=g` 时触发 plum 分派错误（`is_scalar(JitTracer)` ambiguous，netket 与本机 jax 版本不兼容）。改用数值等价的组合即可绕过：

```python
sr = nk.optimizer.SR(qgt=nk.optimizer.qgt.QGTJacobianDense(holomorphic=False),
                     solver=nk.optimizer.solver.svd, diag_shift=1e-3)
```

## 五、对 NES-VMC 分层冻结流程的建议

1. **冻结态必须用收敛后的本征态**（FCI/VMC 收敛态），冻结 HF 行列式这类非本征态要么用一般形式 (I−P)H(I−P)，要么接受冻结不干净。
2. **参考态命名纠偏**：把流程里 `all_states()[0]` 的"HF reference"改为真实 HF 行列式 `[1,0,0,0,1,0,0,0]`（或按 `states_to_numbers` 显式构造）。
3. **训练目标哈密顿量加 λP 位移**（λ 略大于目标激发能级），避免零模吸引导致态塌缩回已冻结态；评估能量时用未位移的 H_perp。
4. **激发态网络用复参数**；若能量卡在明显偏高的平台，优先检查 ansatz 符号结构能力与初始化，再怀疑投影构造。
5. 小系统验证流程：先 ED 对照谱（{0}∪{E_k}），再上 VMC——本文脚本即是该模板，可直接推广到"冻结多个态"（P_F = Σ|φ_m⟩⟨φ_m|，公式不变）。
