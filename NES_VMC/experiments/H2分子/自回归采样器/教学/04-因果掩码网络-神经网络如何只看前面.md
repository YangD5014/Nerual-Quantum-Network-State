# 第 04 章 · 因果掩码网络：神经网络如何"只看前面"

> 第 03 章要求"位置 i 的输出只依赖 x₍<i₎"。一个普通的 MLP 把 8 个输入
> 全部喂给每一层，天生就"全看"。本章讲怎么用一个权重矩阵乘法，
> 把"只看前面"**焊死**在网络结构里，并且一次前向算出全部 8 个条件。

## 4.1 先想清楚 naive 做法有多贵

最直白的实现：要算 ℓᵢ(x₍<i₎)，就构造一个"输入只有前 i 位"的小网络单独前向。
采样一个样本要 8 次独立前向，训练一个 batch 还要 ×3000。能跑，但浪费——
这 8 次前向算的其实是**同一个网络在不同前缀长度上的截断**。

GPT 的做法是：把前缀**补零成定长向量**一次喂进去，但用掩码保证
"第 i 路输出在计算时物理上碰不到第 j ≥ i 位的任何信息"。
我们照搬这个思路到一个两层 MLP 上。

## 4.2 网络长什么样

代码：[CausalMaskedARNQS](file:///Users/yangjianfei/mac_vscode/神经网络量子态/NES_VMC/experiments/H2分子/自回归采样器/ar_nqs.py#L70-L106)。

```
输入 x: (…, 8) 0/1
层1  l1: 8 → 32        （32 = 8 位置 × h，h = hidden_per_site = 4）
层2  l2: 32 → 32
头   head: 32 → 24     （24 = 8 位置 × 3 通道：ℓ, φm, φd）
输出 reshape 成 (…, 8, 3)
```

关键设计：**每一层的宽度都按"位置"分块**。
层 1/2 的第 i 块是 h 个神经元，记作单位 (i, k)，k = 0..3。
这样"输出 i 只看前缀"就有了一句可执行的翻译：

> 单位 (i, k) 的所有入射权重，只允许来自位置 j < i（或 j ≤ i，见下文）的输入。

不满足这个条件的权重，在每次前向时**乘以一个 0/1 掩码矩阵**强制清零。

## 4.3 三层掩码的精确形式

掩码在 [_masks](file:///Users/yangjianfei/mac_vscode/神经网络量子态/NES_VMC/experiments/H2分子/自回归采样器/ar_nqs.py#L87-L97) 里构造。
记 `lt[i,j] = (j < i)`、`le[i,j] = (j ≤ i)`。
nnx.Linear 的 kernel 布局是 `(in, out)`，掩码形状必须和 kernel 逐元素对齐：

| 层 | kernel 形状 | 掩码 | 含义 |
|---|---|---|---|
| l1 | (8, 32) | `M1[j, i·h+k] = (j < i)` | 位置 i 的隐单元只吃 **严格更早** 的输入位 |
| l2 | (32, 32) | `M2[(j,m), (i,k)] = (j ≤ i)` | 位置 i 的隐单元可吃位置 **≤ i** 的上层隐单元 |
| head | (32, 24) | `M3[(j,m), (i,c)] = (j ≤ i)` | 输出 i 可吃位置 ≤ i 的隐单元 |

**为什么第一层是严格 <，后面两层是 ≤？这是本章最容易搞错的地方。**

- 输入层没有"位置 i 的隐单元"这种中间产物，位 i 的输入 xᵢ 本身就是未来信息，
  必须严格屏蔽（j < i）。
- 层 1 的位置 i 块**已经**只依赖 x₍<i₎（上一行保证的）。所以层 2 的单位 (i,k)
  吃层 1 的单位 (i,m) **不泄漏任何未来**——它吃的只是"前缀的函数"。
  于是层内允许 j ≤ i。
- 同理 head 的位置 i 输出可以吃层 2 的位置 ≤ i。

用归纳语言说：掩码保证的不变量是"**位置 i 的一切中间量都是 x₍<i₎ 的函数**"。
第一层用 `<` 建立基例，之后每层用 `≤` 保持归纳步。

> **踩坑实录（值得记住）**：初版代码把 M2/M3 写成了 `le.T` 广播，
> 方向恰好反了（变成"只看后面"），结果归一化自检 Σ|ψ|² = 0.885 直接露馅。
> `lt/le` 的索引方向是这类代码的头号杀手，改掩码后**必须跑归一化自检**（第 06 章）。

## 4.4 掩码怎么乘上去

前向就是普通的矩阵乘，只是 kernel 先逐元素乘掩码
（[__call__](file:///Users/yangjianfei/mac_vscode/神经网络量子态/NES_VMC/experiments/H2分子/自回归采样器/ar_nqs.py#L99-L106)）：

```python
hh = jnp.tanh(x @ (self.l1.kernel * M1) + self.l1.bias)
hh = jnp.tanh(hh @ (self.l2.kernel * M2) + self.l2.bias)
out = hh @ (self.head.kernel * M3) + self.head.bias
```

`kernel * M` 把被禁的权重置零，**梯度也同时被置零**（乘的是常数掩码，
autodiff 自然给出对应参数梯度为 0），所以被掩掉的位置永远不会"复活"。
bias 不掩：位置 i 的 bias 是常数，不含任何 x 的信息，不违反因果性。

参数总量：l1 8×32+32 = 288，l2 32×32+32 = 1056，head 32×24+24 = 792，
共 **2136** 个实参数——比典藏 FFNN（8→20→20→2 头）还小，
但换来了按构造归一化 + 精确采样。

## 4.5 一次前向 = 全部 8 个条件分布

现在回答 4.1 的"浪费"问题。喂进完整串 x（8 位全给），
由因果性，输出的第 i 行 `(ℓᵢ, φmᵢ, φdᵢ)` **只依赖 x₍<i₎**——
后面几位喂进去的是垃圾值也无所谓，它们的信息被掩码拦在门外。

所以：

- **评估 logψ(x)**：1 次前向出全部 8 行，按第 03 章公式拼装。
  （典藏 FFNN 也是 1 次前向，这里没有变贵。）
- **采样**：逐位生成时，第 i 步把当前部分串 x（未填的位是 0）整串喂进去，
  取第 i 行。8 步 = 8 次前向，但每次都是全 batch（3000 样本）并行，
  实测整步 ~0.85 s，完全可接受。

## 4.6 因果性怎么验证

不能只靠"我觉得掩码写对了"。测试方法（自检脚本，第 06 章）：

```
取任意串 x，翻转第 j 位得 x'；
前向比较所有输出行：要求 i > j 的行逐元素相等（diff = 0）。
```

实测结果：**diff = 0.0**（严格相等，不是"接近"——掩码是精确的 0/1 乘法）。
配合 Σ|ψ|² = 1 − 1e-16 的归一化自检，两条一起构成"网络结构正确"的充分证据。

## 4.7 与 Transformer 因果掩码的对应关系

如果你见过 GPT 的注意力掩码，对照记忆：

| | GPT (Transformer) | 本实现 (MLP) |
|---|---|---|
| 掩码对象 | 注意力矩阵 A[i,j]，屏蔽 j > i | 全连接 kernel，屏蔽"未来位置"的入射权重 |
| 位置分块 | 天然按 token | 人为把宽度排成 位置×通道 (n·h) |
| 输出 | 下一 token 分布 | 下一位的 (ℓ, φm, φd) |
| 关键不变量 | 第 i 个 token 的输出只依赖 ≤ i | 同 |

本质是同一件事：**把"信息只能从过去流向未来"实现为权重矩阵上的稀疏模式**。
MLP 版本的好处是掩码是静态常数，不需要任何注意力机制。

## 4.8 本章小结

1. 把每层宽度排成"位置 × 通道"的块结构，因果性 = 对入射权重按位置块屏蔽。
2. 第一层用严格 `<`（输入位是未来），后续层用 `≤`（同位置隐单元只是前缀的函数）。
3. 掩码是常数 0/1 矩阵，逐元素乘 kernel，梯度同步被屏蔽；bias 无需掩码。
4. 一次前向输出全部 8 个位置的 (ℓᵢ, φmᵢ, φdᵢ)，评估 logψ 的成本与全局 FFNN 相同。
5. 改掩码必跑两个自检：因果 diff = 0；Σ|ψ|² − 1 < 1e-16。历史上 le.T 方向错误
   就是被 0.885 的归一化偏差抓住的。
