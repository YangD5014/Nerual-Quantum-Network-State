## 3. 失败直接原因：数值溢出

```
Step   0 | E: 0.55881917 ± 0.008338 | FCI: -1.02613572 | Error: 1.584955
Step  50 | E: nan ± nan | FCI: -1.02613572 | Error: nan
```

**NaN 出现的位置**：`compute_qgt` 函数中 `jnp.eye(qgt.shape[0])`

```python
# NES_VMC_H2_631G.py 第 225 行
qgt_reg = qgt + diag_shift * jnp.eye(qgt.shape[0])
```

## 4. 深层原因分析

### 4.1 Hilbert 空间复杂度增加

| 系统 | STO-3G | 6-31G |
|------|--------|-------|
| 分子轨道 | 2 | 4 |
| 自旋轨道 | 4 | 8 |
| sampler_edges | 2 | 6 |
| 参数数量 | ~100 | ~300+ |

6-31G 的 Hilbert 空间更大，导致：
- QGT 矩阵更大 (n_params × n_params)
- 特征值分布更分散，病态程度更高
- `jax.grad(..., holomorphic=True)` 计算的梯度更容易出现极端值

### 4.2 学习率过大

```python
# Netket_Sampler_631G
optimizer = optax.sgd(learning_rate=0.1)  # ❌ 太大

# 自然梯度VMC
optimizer = optax.sgd(learning_rate=0.01)  # ✅ 合适
```

0.1 的学习率在 STO-3G 上可能勉强工作，但在 6-31G 上会导致：
- 参数更新过大
- 波函数崩塌 → log ψ 出现极端值 → 指数爆炸 → NaN

### 4.3 diag_shift 过小

```python
# Netket_Sampler_631G
qgt_reg, qgt_unravel_fun = compute_qgt(machine, params, samples, diag_shift=0.1)  # ✅ 较大

# 自然梯度VMC
qgt_reg, qgt_unravel_fun = compute_qgt(machine, params, samples, diag_shift=0.001)  # ⚠️ 较小
```

等等，这里 `Netket_Sampler_631G` 的 diag_shift 是 **0.1**（较大），而自然梯度VMC 是 **0.001**（较小）。

但更大的 diag_shift 应该让 QGT 更稳定才对...

**关键发现**：NaN 出现在 `jnp.eye` 而不是 QGT 求逆。这可能是因为：
- `qgt.shape[0]` 变成了 Python scalar 但 QGT 仍是 complex dtype
- JAX 对 complex identity matrix 的处理问题

## 5. 为什么 6-31G 之前能收敛到 HF 态？

看之前成功运行的输出：

```
Step  50 | E: -0.94605227 ± 0.000000 | FCI: -1.02613572 | Error: 0.080083
```

它收敛到了 **HF 能量 (-0.9461 Ha)**，而不是 FCI 能量 (-1.0261 Ha)。这说明：
1. 当时的学习率和 diag_shift 使得训练稳定
2. 但被困在 HF 态的局部最小值

现在的运行出现 **NaN**，说明：
1. **环境/版本变化**：可能 JAX 或 NetKet 版本更新导致行为变化
2. **参数不一致**：当前运行使用的参数与之前不同

## 7. 修复建议

### 方案 A：降低学习率 + 调整 diag_shift

```python
optimizer = optax.sgd(learning_rate=0.01)  # 从 0.1 → 0.01
qgt_reg, qgt_unravel_fun = compute_qgt(machine, params, samples, diag_shift=0.01)  # 从 0.1 → 0.01
```

### 方案 B：改用更稳定的 QGT 求逆（SVD）

```python
# 替换 jnp.linalg.solve 为 SVD
U, s, Vh = jnp.linalg.svd(qgt_reg, full_matrices=False)
sinv = 1.0 / (s + diag_shift)
natural_grad = Vh.T @ (sinv[:, None] * (U.T @ grad_flat))
```

### 方案 C：使用 NetKet 内置 VMC 驱动

这是最可靠的方案，NetKet 内部已经处理了所有数值细节：

```python
gs = nk.driver.VMC(
    ha,
    nk.optimizer.Sgd(learning_rate=0.1),
    variational_state=vstate,
    preconditioner=nk.optimizer.SR(diag_shift=0.1, holomorphic=True),
)
gs.run(400)
```

### 方案 D：简化网络规模

```python
# 6-31G 已经是 8 个自旋轨道，不需要 hi.size*2 的隐藏层
model = SingleStateAnsatz(hi.size, hidden_dim=16, rngs=rngs)  # 固定为 16
```

## 8. 教训总结

1. **不要直接用 `jnp.eye` 处理 complex 矩阵** — 可能导致类型不匹配
2. **大 Hilbert 空间需要更小的学习率** — 参数越多越容易震荡
3. **QGT 求逆应该用 SVD** 而不是 `jnp.linalg.solve` — 更数值稳定
4. **优先使用成熟库**（NetKet）而不是自己实现 — 避免踩坑
