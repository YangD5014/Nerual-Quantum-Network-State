# 自制采样器性能分析报告

## 问题概述

对比分析两个做相同任务的VMC（变分蒙特卡洛）代码：
- **自然梯度下降 VMC.py**：使用NetKet内置的MetropolisSampler ✅ 运行完美
- **自然梯度下降-自制 Sampler.py**：使用自制MCMC采样器 ❌ 速度慢、收敛慢

---

## 核心问题分析

### 🔴 致命问题 1：每步重新创建模型（最关键！）

**第一个代码（第223-231行）：**
```python
for step in range(N_ITER):
    # 1. 采样 - 使用统一的 machine
    sampler_state = sampler.reset(machine, params, sampler_state)
    samples, sampler_state = sampler.sample(...)
```

**第二个代码（第314-324行）：**
```python
for step in range(N_ITER):
    # 1. 采样 - 每次都重新创建 machine！！！
    current_model = nnx.merge(graphdef, params)  # ❌ 多余
    current_machine, graphdef, params = create_machine(current_model)  # ❌ 重复操作
    samples = mcmc_sampler(...)
```

**影响：**
1. **梯度计算不一致**：第328行 `forces_expect_hermitian(current_machine, params, samples)` 使用的是新创建的machine，而第332行 `compute_qgt(current_machine, params, samples, ...)` 也是新创建的machine。**但 params 变量被重新赋值了！** 这导致梯度计算和QGT计算使用的参数可能不一致。

2. **JIT编译开销**：每次循环都调用 `create_machine` 会触发JAX的重新追踪和编译，虽然有 `@jax.jit` 装饰器，但传入的参数结构变化会导致重新编译。

3. **变量覆盖问题**：
   - 第316行：`current_model = nnx.merge(graphdef, params)`
   - 第317行：`current_machine, graphdef, params = create_machine(current_model)`
   - 这里 `params` 被重新赋值为 `state`，虽然值相同，但变量语义混乱

---

### 🔴 致命问题 2：MCMC链不连续

**第一个代码（NetKet采样器）：**
```python
sampler_state = sampler.reset(machine, params, sampler_state)  # 重置但保持结构
samples, sampler_state = sampler.sample(
    machine, params, state=sampler_state, 
    chain_length=20
)
```

NetKet的采样器：
- 维护 **100个独立的chain**（`n_chains=100`）
- 每个chain在参数更新后保持连续性
- 使用 **sweep_size=32** 进行热化，减少自相关性

**第二个代码（自制采样器）：**
```python
samples = mcmc_sampler(
    n_samples=N_SAMPLES,
    n_warmup=200,
    initial_state=hi.all_states()[0],  # ❌ 每次从固定状态开始！
    edges=((0, 1), (2, 3)),
    log_pdf=current_model,
    seed=21
)
```

**影响：**
1. **破坏马尔可夫链连续性**：每次迭代都从 `hi.all_states()[0]` 重新开始，导致：
   - 每次迭代前200步都是"预烧"期，浪费计算资源
   - 样本自相关性强，不独立
   - 有效样本数远低于实际采样数

2. **采样效率低**：NetKet的100个chain相当于并行运行100条独立的马尔可夫链，而你的实现每次只运行1条链。

3. **收敛慢**：由于样本质量差（自相关性强），能量方差估计不准，自然梯度计算不稳定，导致收敛慢。

### 🟡 问题 3：采样器实现细节差异

**NetKet采样器优势：**
```python
single_rule = nk.sampler.rules.FermionHopRule(hilbert=hi, graph=g)
sampler = nk.sampler.MetropolisSampler(hi, rule=single_rule, n_chains=100, sweep_size=32)
```

- **n_chains=100**：并行采样100条链，充分利用硬件
- **sweep_size=32**：每32步做一次测量，减少自相关
- **自动优化的proposal**：NetKet内部使用高效的跳跃规则

**自制采样器问题：**
```python
@partial(jax.jit, static_argnums=(0, 1, 3, 4, 5))
def mcmc_sampler(n_samples, n_warmup, initial_state, edges, log_pdf, seed=42):
    key = jax.random.PRNGKey(seed)  # ❌ 每次都用相同seed
    ...
```

- 每次使用相同seed（seed=21），虽然有预烧，但不够高效
- 只运行1条链，没有并行化

### 🟡 问题 4：变量作用域混乱

**第二个代码第316-317行：**
```python
current_model = nnx.merge(graphdef, params)
current_machine, graphdef, params = create_machine(current_model)
```

问题：
1. `current_model` 和 `current_machine` 命名混淆
2. `params` 被重新赋值为 `state`，后续使用时容易混淆
3. 第328行和331行都使用 `current_machine`，但第332行的 `params` 实际上已经是新创建的state了

**正确的做法应该是：**
```python
# 保持 machine 不变，只在初始化时创建一次
machine, graphdef, params = create_machine(model)  # 只在训练开始时创建一次

for step in range(N_ITER):
    # 采样时直接使用 machine，不需要重新创建
    samples = mcmc_sampler(n_samples=N_SAMPLES, n_warmup=200,
                          initial_state=hi.all_states()[0],
                          edges=((0, 1), (2, 3)),
                          log_pdf=machine,  # 直接传入 machine
                          seed=21)
    
    # 计算时直接使用 params，不需要重新赋值
    energy, energy_std, grad = forces_expect_hermitian(machine, params, samples)
    qgt_reg, qgt_unravel_fun = compute_qgt(machine, params, samples, diag_shift=0.001)
```

## 性能差异量化

| 指标 | 第一个代码 | 第二个代码 | 影响 |
|------|-----------|-----------|------|
| 采样方式 | 100条并行链 | 1条链 | 样本独立性问题 |
| 链连续性 | ✅ 保持 | ❌ 每次重置 | 收敛速度 |
| 模型重建 | ❌ 每步重建 | ❌ 每步重建 | JIT编译开销 |
| 预烧开销 | ✅ 已预烧 | ❌ 每步200步 | 计算浪费 |
| 有效样本数 | ~20000 | ~1000 | 梯度估计精度 |

## 根本原因总结

1. **训练循环中的重复操作**（最关键）：每次迭代都重新创建machine，导致：
   - JIT重新编译开销
   - 梯度计算和QGT计算可能不一致
   - 变量语义混乱

2. **MCMC链不连续**：每次从固定状态开始，浪费预烧步骤，样本自相关性强

3. **采样效率低**：100条并行链 vs 1条链，样本质量差异大

4. **自然梯度计算不稳定**：由于样本质量问题，QGT矩阵估计不准，自然梯度方向偏差大

## 改进建议

### ✅ 最小改动修复

```python
# 训练开始时创建一次
machine, graphdef, params = create_machine(model)
opt_state = optimizer.init(params)

for step in range(N_ITER):
    # 直接采样，不需要重建machine
    samples = mcmc_sampler(
        n_samples=N_SAMPLES,
        n_warmup=200,
        initial_state=hi.all_states()[0],
        edges=((0, 1), (2, 3)),
        log_pdf=machine,  # 直接用machine
        seed=step  # 使用不同seed或维护一个PRNG key
    )
    
    # 直接计算，不需要重新创建
    energy, energy_std, grad = forces_expect_hermitian(machine, params, samples)
    qgt_reg, qgt_unravel_fun = compute_qgt(machine, params, samples, diag_shift=0.001)
    
    # 自然梯度更新
    grad_flat, grad_unravel_fn = flatten_util.ravel_pytree(grad)
    natural_grad = jnp.linalg.solve(qgt_reg, grad_flat)
    natural_grad = grad_unravel_fn(natural_grad)
    
    # 更新
    updates, opt_state = optimizer.update(natural_grad, opt_state, params)
    params = optax.apply_updates(params, updates)
```

### ✅ 进一步优化：保持MCMC链连续性

```python
# 在训练循环外维护一个当前状态
current_state = hi.all_states()[0]

for step in range(N_ITER):
    # 只热化少量步，保持链的连续性
    if step == 0:
        n_warmup = 200  # 第一次充分预烧
        current_state = hi.all_states()[0]
    else:
        n_warmup = 10  # 之后只热化少量步
    
    samples = mcmc_sampler(
        n_samples=N_SAMPLES,
        n_warmup=n_warmup,
        initial_state=current_state,  # 使用上一次的状态
        edges=((0, 1), (2, 3)),
        log_pdf=machine,
        seed=step
    )
    current_state = samples[-1]  # 保存最后状态用于下次迭代
```

### ✅ 高级优化：并行多链

```python
def parallel_mcmc_sampler(n_chains, n_samples_per_chain, n_warmup, initial_states, edges, log_pdf, seed):
    """并行运行多条马尔可夫链"""
    keys = jax.random.split(jax.random.PRNGKey(seed), n_chains)
    
    def sample_single_chain(args):
        key, init_state = args
        samples = mcmc_sampler(n_samples_per_chain, n_warmup, init_state, edges, log_pdf, seed=0)
        return samples
    
    all_samples = jax.vmap(sample_single_chain)((keys, initial_states))
    return all_samples.reshape(-1, hi.size)
```

## 结论

第二个代码慢和收敛慢的根本原因是：

1. **每步重新创建模型**：导致JIT编译开销和变量混乱
2. **MCMC链不连续**：每次重置导致样本质量差
3. **单链采样**：没有利用并行化，样本自相关性强

修复后，自制采样器的性能应该能接近甚至超过NetKet采样器，因为你可以针对具体问题做定制优化。

---

**建议优先修复"每步重新创建模型"问题，这是最关键的瓶颈！**
